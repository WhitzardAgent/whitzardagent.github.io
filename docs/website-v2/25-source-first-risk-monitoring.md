# NUWA Index 下一版：来源提取、风险监测与自主评测

规划日期：2026-10-25。当前检索截止日：2026-10-25。本文是下一版设计稿，不代表新数据已公开入库、定期任务已启动或自主评测已执行。

## 1. 定位与产出

**NUWA Frontier AI Safety Index 是由女娲实验室维护的前沿 AI 风险研究与模型证据监测系统。**

公开知识库承担研究底座；持续监测形成模型风险证据档案；证据缺口指导 NUWA 自主评测；经过论证的方法逐步构成女娲自己的评测科学。网站是这一研究流程的公开表达。

需要持续回答：

1. 全球研究正在发现、评测和应对哪些前沿风险？
2. 某个具体模型／智能体系统，在什么条件下获得过哪些风险相关结果？
3. 新报告、新模型、协议修订和结果更正带来了什么变化？
4. 多个来源指向同一实验，还是构成独立证据？
5. 哪些判断已有支持，哪些分歧尚未解决？
6. NUWA 应优先补测哪些问题，怎样形成可复核的新证据？

“风险水位”对外呈现为**多维风险证据画像与变化**。首版继续使用具体指标和协议，不生成跨领域总分、风险概率或安全认证。未来综合指标若成为研究目标，应单独开展构念效度、权重、敏感性与外部检验研究。

### 保留的 NUWA 研究体系

- 机制模型：Propensity 与 Capability 共同关联 Behavior；Swarm / Multi-agent dynamics 是可选系统层扩展。
- 风险主题：Agentic Risks 下设 Autonomy、Deception；Dual-Use Risks 下设 Cybersecurity、CBRN、Disinformation、Autonomous Physical Harm。
- 五类研究功能：Risk Discovery、Risk Evaluation、Risk Monitoring、Risk Investigation、Risk Governance，继续用于 Library。
- P／C／B 是测量维度；同一协议的改造版本必须重新核查构念。任务成功率、行为发生率与模型内在倾向不能自动互换。

## 3. 总体流程

**发现来源 → 冻结版本 → 单来源 subagent 提取 → 程序校验 → 独立复核 → 实体与协议消歧 → 证据去重 → 可比性判定 → 监测与综合 → 缺口与自主评测 → 审阅发布**

### 来源与任务单位

任务单位是 **SourceVersion**。同一篇论文的 HTML／PDF／DOI 别名归入一个文档身份；每次实质修订、榜单数据变化和适用的渲染规则变化具有独立快照。

- System Card／Model Card：完整记录相关章节、表格、附录、引用结果及未公开结果。
- 第三方评估报告：逐节提取实际使用的协议、改造、模型版本、结果及报告中的他方对照数据。
- Benchmark 官网：配套读取页面、官方结构化数据、版本说明和必要的计分／展示规则；“JSON 中存在”不自动等于“作者当前对外展示”。
- 研究论文、方法及事件调查：没有数字也能收录，保留发现、研究问题、论证、方法、限制与关联。

首轮将现有相关来源去重成有限 manifest，逐项标记新建任务、已完成、需要重提、无法获取和不适用。先覆盖目前实际支撑模型档案与结果的来源，再扩展十家开发机构及已确定第三方机构；按覆盖审计结束一批，不追求卡片数量。

### 单来源 worker 的责任

每份来源先由专属 subagent 提取。它读取该 SourceVersion、必要的关联数据文件及字段定义，不读取其他报告的成绩来补全当前来源。大报告可由一个负责该文档的 lead worker 分发只读章节任务，最终统一覆盖清单。

输出统一的私有 ExtractionPackage：

- 来源身份、版本、URL、抓取时间、SHA-256、文档公开／修订日期及其依据。
- 章节覆盖表：已提取、仅定性、未披露、图中无精确值、外部引用、访问失败、不相关、待复核。
- 原始 Observation 与研究 Claim；每项附 PDF 页码／表格／行列、HTML 定位或 JSON Pointer。
- 原始值／单位／限定语／原始指标名；样本、分子、分母、区间及缺失原因。
- 模型、端点、Harness、工具、预算、尝试次数、任务集版本、判别器及防护配置。
- 开发机构、文档发布方、榜单托管方、结果报告方、提交方和实际执行方，未确定的角色留空。
- 原文发现与解释边界；模型缺口、内部矛盾、继承值和待追溯引用。
- 任务输入哈希、worker／prompt／parser 版本、处理状态及校验日志。

结构化文件优先由程序精确解析；subagent 负责判断字段语义、条件和局限。只有结果图且无精确数值时保留原图，不估柱高。来源中的说明、代码和指令作为研究材料读取，不执行。原始危险任务、利用材料和敏感细节不进入公开知识库。

单来源 worker **不直接编辑公开 catalogue、不解决跨来源冲突、不宣布风险结论**。恢复任务按 source hash＋parser／prompt 版本复用已完成章节，避免重复工作；每个来源都有最终覆盖状态。

## 4. 证据单位与数据结构

沿用 Model、Assessment、ProtocolVariant、ResearchWork、Organization、EvidenceRecord 等现有实体和稳定 ID，增加小型独立实体，而不是重写全部数据。

| 实体 | 核心职责 |
|---|---|
| SourceVersion | 内容身份、来源版本、哈希、时间语义、原始材料定位 |
| ExtractionJob / ExtractionPackage | 私有任务、覆盖清单、原始抽取、校验与复核记录 |
| SourceObservation | 原文某处实际报告了什么，保留原始字段、单位、继承与角色 |
| EvidenceLineage | 一项结果由哪些报告转载、引用、修订或独立复现 |
| ComparisonSet | 适用的任务／指标／协议／配置条件、差异与允许的操作 |
| MonitoringSignal / Synthesis | 经过审阅的变化说明、适用范围、支持／反向证据及引用 |
| EvidenceGap / EvaluationPlan | 缺什么、为何重要、是否能补测、计划及运行凭据 |

### 不混用的身份与时间

- Model 是具体发布版本或端点，不以模型家族名覆盖所有版本；精确身份未核实的记录保留原名，不强制挂到一个已知版本。
- Harness 维护者、模型开发者、报告发布方与评测执行方不互相推断。官网采用他方提交数据时明确标注来源与角色缺失。
- 分别保存模型发布事件、实际实验时间、报告发表／修订、榜单行的原始日期、首次发现和抓取时间。
- 未定义的 Date 字段保存为 `reportedDate` 和 `semantics: unspecified`；文件时间、快照编号和父行日期不代替实验日期。
- 历史截止视图仅使用当时已公开或已捕获的具体版本；未知公开时间保持保守。回溯模型发布序列与“当时已知证据”是两种视角。

### 原始值、转换与缺失

原始报告值与 NUWA 派生值分开。比例转百分比需保留输入、公式、舍入和版本；页面报告的百分比优先保留原文精度。不同分母、计分模式、预算、尝试次数、补齐／插补和统计估计各自成项。运行失败、拒答、防护阻断、访问受限、没有结果与观测零值使用不同状态。

## 5. 从多个来源形成监测结果

### 第一步：建立出处关系

先判断报告是在执行评测、复用别人数据、复现实验，还是转述一个结论。同一实验在官网、System Card 和第三方文章出现三次，只构成一个已确认实验的多条出处；不能据此声称三次独立验证。无法确定是否同一运行时保留 `possibly-same-run`，不强行合并。

数值冲突建立 ConflictRecord，包含各自版本、定位和差异，进入原始材料复核。更正追加关系，历史快照不重写。

### 第二步：判定能够做什么比较

每个 ComparisonSet 有审阅后的判定和理由：

1. **Source-reported group**：保留原文同组结果及配置差异，可并列呈现，不扩大其比较结论。
2. **Descriptive alignment**：相同构念但仍存在已知差异，允许分面／散点，配置持续可见。
3. **Matched comparison**：任务集、指标、评分、预算与受测对象等关键条件已核实，才提供相应排序或差值。
4. **Stable longitudinal series**：跨期条件和版本处理规则已确定，才连接趋势线。
5. **Not comparable**：分开展示，解释关键差异。

缺失关键条件时不能进入更高层级；同名 Benchmark 不构成相同协议。对 Harness、预算等差异应依据研究问题作判断：比较整体系统可以允许已声明的系统差异，但不能据此隔离出模型本身的因果贡献。

### 第三步：生成有依据的信号

首期监测五类变化：新模型／新报告、新风险发现、协议稳定组内的结果变化、来源更正与研究分歧、证据覆盖与时效变化。每个 Signal 固定给出“发生了什么、依赖什么证据、条件是否一致、支持什么、不能推出什么、NUWA 后续行动”。

自动生成候选信号，科学解释按批次审阅。单篇报告无显著发现不等于没有风险；多个相关结果不自动构成因果证据；受控场景行为不外推成现实失控概率。

“综合”包括多源支持关系、独立性、矛盾、覆盖和条件解释，不自动把分数标准化后求平均。首期不计算证据可信度百分数或来源声誉分，不用机构名替代实验质量判断。

## 7. 由缺口驱动 NUWA 自主评测

EvidenceGap 包含模型、主题、研究问题、协议、缺失原因、现有证据、预期贡献、复现可行性和建议优先级。缺口先区分：尚未检索、原文未披露、待提取、身份／配置待核实、协议不可比较、结果过期、访问／防护限制，以及真正缺少实验。

完成检索和消歧后仍需实验的问题，再生成 EvaluationPlan：

1. 明确能力、倾向或行为问题；说明这次实验能够支持哪些判断。
2. 固定模型端点、任务集及版本、Harness、提示、工具、预算、重试、判别器、抽样、停止规则和统计报告方式。
3. 先做最小试运行检查任务与评分器，再进行预先约定规模的运行；基础设施失败和模型结果分开记录。
4. 保存运行 manifest、版本／commit、任务与配置哈希、实际时间、逐样本状态、汇总生成程序和可公开凭据。
5. 根据需要安排人工复核、对照、复现及敏感性分析；区间根据实际设计计算，不为外部数据补造未报告区间。
6. 结果标注 **NUWA evaluation**；外部结果继续标注实际来源。Replication、Extension 与 NUWA 原创协议各自成项。

优先补测可在受控现有基础设施中复现、解释价值明确的协议；预算、访问方式和运行范围形成单独可审阅执行清单。本轮不启动评测，也不迁移网站。高风险领域公开适当汇总及方法概述，原始敏感材料留在受控工作区。

### 评测科学研究线

自主评测的研究交付还包括五项方法工作，不能只有运行数量：

- **构念效度**：为每个协议说明测量的是任务能力、条件性行为倾向还是已观察行为；行为记录不能直接揭示内在意图。
- **能力诱发与条件控制**：记录 Harness、工具、预算、指令和防护对结果的影响。研究模型本身时控制这些变量；研究完整系统时明确它们属于被测对象。
- **评分有效性**：核查自动判别器、人工复核一致性、任务泄漏／评测感知、样本代表性，以及实验失败的处理方式。
- **机制与系统扩展**：围绕 Propensity、Capability 到 Behavior 的条件关系设计研究；多智能体研究单独记录结构、共享状态、协同规模及监测范围，通过对照检验放大效应。
- **外推边界**：区分受控实验发现、真实部署观测和现实危害概率，研究何种证据能够支持部署判断。

每个 NUWA 协议交付一个方法档案：研究问题、威胁模型、构念、任务与抽样、条件、指标、统计方法、判别器核查、效度威胁和可推出／不可推出的判断。标准证据陈述采用：在条件 A 下，系统 B 使用 Harness C，对任务族 E，在 D 次已定义试验中获得结果 X；原始来源与 NUWA 解读分别列出。

## 8. 技术路线与维护

网站继续 Astro 静态输出、现有 React islands／Tailwind／Markdown／JSONL 与 GitHub Pages。采集与研究任务在私有离线管线运行，公开站只读取通过校验的版本快照；当前无需新 CMS、图数据库或服务器迁移。

- 私有目录：原始材料、抓取 manifest、worker 任务、候选包、冲突与草稿，使用项目专用环境变量 `NUWA_PRIVATE_ROOT`。
- 公共仓库：经审阅的研究元数据、结果、出处、比较定义、信号与方法；保留历史 schema 和旧 CSV 列含义。
- 调度：默认按周检查已选来源及失效／变更；新模型报告可人工触发优先任务；月度综合。未变化的快照复用，不重复提取；任务失败可恢复。频率为下一版建议，本轮不启用自动化。
- 发布：程序通过不等于科学审阅通过。新来源／协议／实体冲突／科学解释需审阅；未来已批准适配器中的纯事实更新才可按既定规则自动处理。

| D 监测页面 | 模型画像、主题趋势、来源详情、变化记录及报告草稿 | 图表来源随切换；可追溯每个信号；缺口不呈现为低风险 |
| E 自主评测桥接 | Gap→EvaluationPlan→RunReceipt 数据契约及一个受控试运行样板 | 先审阅执行清单；自有实验与外部实验归属清楚，凭据可追溯 |

每一阶段先交付本地版本。首个公开候选版本要求 A–D 完成；E 的数据接口可先完成，真实实验按单独批准的运行计划安排，不阻塞知识库发布。

验收除现有类型、测试、内容、术语、Research Blog、JSONL、链接与静态构建，还增加：原始数字回读、完整章节处置、角色缺失、同实验多处转载、计分模式分母、父子行继承、公开资格、来源冲突、历史截止、任务中断恢复及各比较层级的测试。中英文覆盖 1440、1200、900／808、390px，验证键盘、触摸、返回、语言切换、静态阅读及 reduced-motion。
